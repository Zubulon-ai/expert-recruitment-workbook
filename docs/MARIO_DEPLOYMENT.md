# 在快手内部 AI Mario 中给 mentor 使用

## 结论

Codex 插件不能默认视为 AI Mario 的原生 Skill 包。只有当 Mario 明确支持 `SKILL.md`、插件清单和对应脚本运行环境时，才能直接导入本仓库结构。

在尚未确认 Mario 原生 manifest 规范的情况下，最稳妥的封装是：

1. 把 [SYSTEM_PROMPT.md](../mario/expert-recruitment-workbook/SYSTEM_PROMPT.md) 作为智能体的系统指令；
2. 把 [KNOWLEDGE_RULES.md](../mario/expert-recruitment-workbook/KNOWLEDGE_RULES.md) 作为知识文件；
3. 用 [TEST_CASE.md](../mario/expert-recruitment-workbook/TEST_CASE.md) 做发布前验收；
4. 根据 Mario 是否具备 Excel/代码工具，选择“直接生成 xlsx”或“先输出结构化表格”。

## 推荐部署步骤

Mario 的界面名称可能随内部版本变化，以下按通用的“创建智能体/创建技能”流程操作：

1. 新建一个内部智能体或技能，名称填写“专家招募表生成器”。
2. 简介填写：“将招募文案和多渠道专家资料整理为统一 Excel，标记疑似重复、报价差异与数据口径冲突。”
3. 将 `SYSTEM_PROMPT.md` 的全部内容粘贴到“系统指令/角色设定/核心提示词”。
4. 将 `KNOWLEDGE_RULES.md` 上传到“知识库/参考文件”。
5. 如果 Mario 支持文件工具，开启读取附件和输出文件权限。
6. 如果 Mario 支持 Excel、表格或代码执行工具，开启相应能力；不要授予与本任务无关的外部写权限。
7. 使用 `TEST_CASE.md` 中的虚拟资料测试，确认不会把缺失字段编造出来，也不会删除疑似重复的候选人。
8. 发布范围优先选择“仅指定成员/仅项目组”，把 mentor 加入可使用名单。

## Mario 能力与交付方式

| Mario 当前能力 | 建议封装 | 最终交付 |
|---|---|---|
| 支持系统提示词与知识文件，支持 Excel 工具 | 系统提示词＋知识规则 | 直接生成 `.xlsx` |
| 支持系统提示词与代码执行，但没有原生 Excel 工具 | 系统提示词＋知识规则＋经内审允许的工作簿脚本 | 生成 `.xlsx` |
| 只支持系统提示词和文本输出 | 系统提示词＋知识规则 | 输出九列 Markdown/TSV，人工导入 Excel |
| 支持原生 Skill 导入 | 向 Mario 管理员获取 manifest 规范后映射本包 | 原生 Skill |

如果 Mario 没有文件创建能力，智能体必须明确说明限制，不能声称已经生成 Excel。

## 发布前需要向 Mario 管理员确认

1. 是否支持自定义系统提示词和知识文件？
2. 是否支持上传或返回 `.xlsx`？
3. 是否有内置电子表格工具，还是只支持 Python/Node 代码执行？
4. 是否支持原生 Skill manifest？必填字段和目录结构是什么？
5. 代码运行环境是否允许第三方依赖，允许哪些库？
6. 智能体的可见范围、日志留存和文件权限如何配置？
7. mentor 是否需要单独申请访问权限？

拿到 Mario 的创建页面截图、帮助文档或 manifest 示例后，可以把本兼容包进一步改成一键导入版本。

## mentor 使用方式

mentor 上传或粘贴招募需求和专家资料后输入：

```text
请按专家招募表标准格式整理下面的资料，生成 Excel；保留所有渠道行，并在备注中标记疑似重复、报价差异和数据口径冲突。
```

追加已有表格时输入：

```text
请在附件中的专家表末尾追加下面的候选人，保持原列顺序和格式，不要覆盖现有内容。
```

## 内部信息安全

- Mario 版本建议只在快手内部可见，并限制到 mentor 或项目组。
- GitHub 仓库继续只存通用规则和虚拟样例；真实专家资料留在获批的内部环境。
- 不在系统提示词中写真实专家姓名、联系方式或项目数字。
- 专家反馈统一视为待交叉验证材料，不作为快手或竞品官方事实。
- 导出文件前检查分享范围、个人信息和内部业务口径。

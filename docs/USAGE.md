# 专家招募表生成器：使用说明

## 1. 适用场景

这个 Skill 用于把微信、邮件或多家专家渠道发来的招募文案与候选人资料，整理为统一的 Excel 专家招募表。它适合：

- 新建一轮专家招募表；
- 在已有 Excel 中追加专家；
- 统一格式、修正换行和列宽；
- 比较不同渠道的报价；
- 标记疑似重复专家；
- 提醒 DAU、预算、转化率等指标的数据口径冲突。

它不会自行核验非公开业务数据，也不会把专家反馈写成公司官方口径。

## 2. 从 GitHub 安装

首次使用，在终端运行：

```text
codex plugin marketplace add Zubulon-ai/expert-recruitment-workbook
```

然后：

1. 重启 ChatGPT/Codex 桌面应用；
2. 打开 Plugins Directory；
3. 选择“专家招募工具”市场；
4. 安装 `expert-recruitment-workbook`；
5. 在一个新任务中开始使用。

仓库是私有仓库。其他人安装前，需要先获得该 GitHub 仓库的访问权限。

## 3. 最简单的调用方式

```text
$expert-recruitment-workbook

请把下面的招募文案和专家资料整理成一个新的 Excel，沿用标准格式，并检查疑似重复专家、报价差异和数据口径冲突：

【招募文案】
……

【渠道A】
……

【渠道B】
……
```

不写 `$expert-recruitment-workbook` 也可以。下面这些表达应当自动触发：

- “把下面的专家整理成新的本地 Excel”；
- “按之前格式生成专家招募表”；
- “把这些新增专家加到已有表格”；
- “统一格式并检查是否有重复专家”。

## 4. 输入要求

输入可以是散乱的转发文本，不要求先整理成表格。尽量提供：

- 招募方向或项目名称；
- 访谈问题和 Test 问题；
- 推荐方；
- 公司、职位；
- 专家背景；
- 话题反馈；
- 可访谈时间；
- 倍率、时薪及是否含税。

缺失字段会留空或标记“待定”，不会猜测。建议保留每家渠道的原始费率描述，以便比较含税状态和报价差异。

## 5. 常用任务示例

### 新建一轮招募表

```text
$expert-recruitment-workbook 根据下面的新需求和候选专家，新建一份 Excel。标题用“激励×电商协同｜专家招募表”，将 Test 问题放在招募问题区末尾。
```

### 追加到已有表格

```text
$expert-recruitment-workbook 在我提供的现有 Excel 中追加下面5位专家。保持原有列、颜色、行高和筛选器，不要重做整张表。
```

### 重点检查重复和报价

```text
$expert-recruitment-workbook 整理下面的候选人，并重点检查不同渠道是否推荐了同一专家；如果时薪可比，在备注中写明价差，但不要删除任何一行。
```

### 只调整格式

```text
$expert-recruitment-workbook 不改文字和数字，只修正这份专家表的列宽、换行、行高、冻结窗格和表头样式。
```

## 6. 默认输出

默认生成一张主表，列顺序为：序号、公司、职位、费率、推荐方、可访谈时间、专家背景、话题反馈、备注。

备注列用于记录疑似重复、报价差异、指标口径冲突、岗位匹配度和其他待确认信息。

最终应交付 `.xlsx`，并完成内容检查、公式错误扫描和至少一次视觉渲染检查。

## 7. 更新 Skill

仓库有新版本时运行：

```text
codex plugin marketplace upgrade expert-recruitment-tools
```

重启桌面应用后生效。

## 8. 数据与权限

- GitHub 仓库只保存规则、脚本和虚拟示例，不保存真实专家资料。
- 不要把真实专家姓名、手机号、访谈记录或内部业务数字提交到仓库。
- 每次任务的真实输入只放在当前授权的工作环境中。
- 分享生成的 Excel 前，需按团队规范检查敏感信息和访问范围。

## 9. 常见问题

### Plugins Directory 中没有出现

先运行 `codex plugin marketplace list`，确认存在 `expert-recruitment-tools`，然后重启桌面应用。

### Skill 没有自动触发

在任务开头显式写 `$expert-recruitment-workbook`。

### 无法生成 Excel

该 Skill 依赖当前环境的电子表格创建能力。如果环境没有可用的工作簿工具或运行依赖，应明确报告阻塞，不应假装已经生成文件。此时可以先输出结构化表格草稿，再换到具备 Excel 能力的环境执行。
